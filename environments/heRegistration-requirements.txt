# pip requirements for the `heRegistration` env. Install with
# `--no-deps` on the CLI AFTER the conda solve — see the README's
# "Recommended" install section and the sibling `heRegistration.yml`
# docstring for the rationale.
#
# Rendering `--no-deps` inside this file is not portable (pip refuses
# it, "no such option") and rendering it inside the yaml pip: block
# breaks on the micromamba versions that pass each pip: entry as a
# requirement string ("Invalid requirement: --no-deps"). So the flag
# lives on the CLI and this file is a plain pinned list.
#
# Why `--no-deps` is load-bearing (do NOT drop it): valis-wsi 1.1's
# declared Requires-Dist caps `pandas<2.0`, `pyvips<3.0`, and
# `scikit-image<0.20`. Its actual code paths run fine with pandas 2.x
# / pyvips 3.x / scikit-image 0.19.x — which is exactly the state the
# working env has. Without `--no-deps`, pip's resolver errors out
# ("ResolutionImpossible: valis-wsi 1.1.0 depends on pandas<2.0.0").
# HEST has similar declared-vs-actual divergences.
#
# Order-independent (pip installs each independently under --no-deps).
#
# numpy is pinned here as a belt-and-braces guard on top of the
# `numpy=1.26.4` pin in `heRegistration.yml`. Without it, a
# `pip install --force-reinstall <any-pkg-with-loose-numpy-bound>` — e.g.
# `pip install --force-reinstall xarray==2023.10.1` (missing --no-deps) —
# re-resolves transitive deps and pulls numpy 2.x, blowing past what
# `fastcluster`'s compiled `.so` supports and yielding
# `_ARRAY_API not found` / `numpy.core.multiarray failed to import`
# at the next `import fastcluster` (or any downstream chain).
# See settylab/TracyY123-nexus#15 comments 5336001245 (numpy drift
# postmortem) and 5334721763 (min-blast-radius env verification).
numpy==1.26.4
#
# xarray pinned to the last release BEFORE the pandas 2.1+
# `NumpyExtensionArray` rename. xarray 2026.1.0 accesses
# `pd.arrays.NumpyExtensionArray` at import time — crashing on
# `pandas 1.5.3` with `AttributeError`. The full diagnostic + why
# `dask.array`'s `errors="ignore"` on optional xarray does NOT
# swallow this (AttributeError, not ImportError) is
# settylab/TracyY123-nexus#15 comment 5335874791.
# The `xarray-*` companions further down are kept at their current
# pins; if they choke on the downgraded xarray, uninstall all four
# (`xarray`, `xarray-dataclass`, `xarray-schema`, `xarray-spatial`)
# — nothing on the register+warp code path calls xarray directly.
